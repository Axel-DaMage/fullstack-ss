# Objetivos de Presentación - Evaluación 2

## Entregable (Encargo Grupal) - 30%

### Documentación Requerida
- **Análisis de Patrones y Arquetipos**: Documento PDF que explique los patrones de diseño y arquetipos seleccionados, justificando su uso.
- **Plan de Branching**: Documento PDF con el detalle de la estrategia de branching utilizada.

### Componentes Frontend
- Archivos y dependencias empaquetados según el estándar **NPM**.
- Archivo `package.json` con dependencias y scripts necesarios.
- Código fuente organizado en carpetas (src, public, etc.).
- Instrucciones en archivo `README.md` para ejecutar y probar los componentes.

### Componentes Backend
- **Backend For Frontend (BFF)**:
  - Código fuente estructurado.
  - Archivo `README.md` con instrucciones para instalación y ejecución.

- **Microservicios**:
  - Código fuente organizado.
  - Archivos de configuración y dependencias.
  - Archivo `README.md` para cada microservicio.

### Arquetipos Maven
- Código fuente de los arquetipos Maven usados como base.
- Archivos de configuración (`pom.xml`).
- Guía breve (`README.md`) sobre cómo usar los arquetipos.

### Repositorios
- Archivo `repositorios.txt` o documento PDF con los enlaces a GitHub:
  - Enlace al repositorio principal del proyecto.
  - Enlaces individuales a cada componente (frontend, BFF, microservicios).
  - Breve descripción de cada repositorio.

### Archivo Comprimido
- Entregar todo en archivo ZIP o RAR siguiendo la estructura indicada.

## Defensa Oral - 70% (Individual)

### Indicadores de Evaluación

1. **Explicación de Patrones de Diseño** (20%)
   - Explicar con claridad la elección y aplicación de patrones en frontend y backend.
   - Destacar cómo cada patrón contribuye a la solución del problema.
   - Demostrar mejora en la mantenibilidad del sistema.

2. **Descripción de Arquetipos y Patrones Arquitectónicos** (20%)
   - Describir la aplicación de arquetipos y patrones arquitectónicos.
   - Justificar la elección para garantizar coherencia, escalabilidad y rendimiento.
   - Explicar el rol del BFF y microservicios.

3. **Estrategia de Branching** (15%)
   - Detallar la estrategia de branching utilizada.
   - Explicar cómo la estructura de ramas favoreció la colaboración.
   - Proporcionar ejemplos de gestión de conflictos.

4. **Buenas Prácticas y Pruebas Unitarias** (15%)
   - Explicar cómo las buenas prácticas resolvieron problemas en frontend y backend.
   - Presentar resultados de pruebas unitarias.
   - Mostrar cobertura de código obtenida.
